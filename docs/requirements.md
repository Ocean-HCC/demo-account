# 需求

本文档记录系统要满足谁、在什么场景下完成什么任务，以及必须成立的规则和外部约束。角色有两个：**程序调用方**，即策略程序或 AI Agent，通过接口使用系统；**账户主人**，即发起者本人，通过网页使用系统。运维关注点并入最后一章的跨角色规则。全部条目已于 2026-09-24 由发起者逐条确认；2026-09-29 按意图去掉 ETF，跨角色规则 1.1、1.4、1.5、1.8、1.9、3.5 的修改逐条确认。

目录

- 程序调用方：1. 开户与账户状态 · 2. 下单与撤单 · 3. 查询 · 4. 事件通知
- 账户主人：1. 总览与对比 · 2. 手动交易 · 3. 持仓与流水 · 4. 绩效统计 · 5. 账户管理
- 跨角色规则和外部约束：1. 交易所与税务规定 · 2. 系统级约束 · 3. 第一版范围边界

## 程序调用方

策略程序或 AI Agent 把本系统当作模拟券商柜台：开户、下单、查询、接收成交通知。

### 1. 开户与账户状态

- 1.1 作为程序调用方，在启动一个新策略时，我需要用指定的初始资金和费用参数创建一个独立的模拟账户，以便该策略的账务与其他账户互不影响。
- 1.2 作为程序调用方，在每次下单前，我需要知道账户是否处于可交易状态，以便账户被冻结时停止下单。

### 2. 下单与撤单

- 2.1 作为程序调用方，在盘中做出交易决策时，我需要按标的、方向和数量（或金额）提交即时成交的订单，并按当时的真实行情成交，以便验证"此刻按信号操作"的实际结果。
- 2.2 作为程序调用方，对成交价格有预期时，我需要提交限价订单，在价格触及时成交，当日未成交自动失效，以便不以任意价格追单。
- 2.3 作为程序调用方，在收盘后做出决策时，我需要提交按次一交易日开盘价成交的订单，以便收盘后决策类策略不必等到次日盘中再下单。
- 2.4 作为程序调用方，需要按收盘价建仓或调仓时，我需要提交按当日收盘价成交的订单。
- 2.5 作为程序调用方，下单后我需要立即得到订单编号，并能随时查询订单处于等待、已成交、已拒绝、已撤销还是已失效状态，以便据此决定后续动作。
- 2.6 作为程序调用方，订单被拒绝或失效时，我需要得到明确原因，例如资金不足、可卖数量不足、非交易时段、停牌、触及涨跌停、不符合申报规则，以便调整决策。
- 2.7 作为程序调用方，订单尚未成交时，我需要能撤销它。
- 2.8 作为程序调用方，在网络异常后重试时，同一笔下单不能被重复执行，以便避免意外重复建仓。

### 3. 查询

- 3.1 作为程序调用方，在决策前，我需要随时查询账户现金、每个持仓的数量、可卖数量、成本、当前市值和浮动盈亏，以及账户总资产，以便计算仓位。
- 3.2 作为程序调用方，在复盘时，我需要拉取账户的成交记录、历史订单和每日净值序列，以便做自己的绩效分析。
- 3.3 作为程序调用方，在下单前，我需要查询当前是否为交易日和交易时段，以及标的的当前价、涨跌停价和是否停牌，以便避免无效下单。

### 4. 事件通知

- 4.1 作为程序调用方，订单成交、被拒绝或失效时，我需要被主动通知，而不必反复轮询，以便及时响应。

## 账户主人

发起者本人通过网页查看所有账户、手动交易、评估策略和管理账户。

### 1. 总览与对比

- 1.1 作为账户主人，打开控制台时，我需要看到每个账户的现金、持仓市值、总资产、当日盈亏和净值曲线，并与基准指数（默认沪深 300）对比，以便判断策略是否跑赢市场。
- 1.2 作为账户主人，同时运行多个策略时，我需要把多个账户的净值曲线放在一起看，以便横向对比。

### 2. 手动交易

- 2.1 作为账户主人，想手动验证想法或干预某个账户时，我需要在网页上对任一账户买入、卖出和撤单，规则与程序下单完全一致，以便手动和程序的结果可比。
- 2.2 作为账户主人，手动下单时，我需要在提交前看到订单预计占用的资金和费用，以便避免因资金不足被拒。

### 3. 持仓与流水

- 3.1 作为账户主人，查看某个账户时，我需要看到持仓明细以及订单和成交历史，并能按标的和时间找到记录，以便核对每一笔交易。

### 4. 绩效统计

- 4.1 作为账户主人，评估策略时，我需要看到每个账户的回合统计，包括胜率、盈亏比、平均持有天数、最大回撤、累计收益和年化收益，以便判断策略质量。
- 4.2 作为账户主人，对照回测结果时，我需要统计口径与常见回测报告一致：回合按先进先出配对，回撤按每个交易日收盘后定版的净值计算，盘中估算值不进入统计，以便直接比较。

### 5. 账户管理

- 5.1 作为账户主人，新建账户时，我需要为账户起名和写备注，以便区分它属于哪个策略。
- 5.2 作为账户主人，想暂停某个策略时，我需要冻结账户，冻结后拒绝一切新订单、持仓和记录只读，并且之后可以恢复。
- 5.3 作为账户主人，想让某个策略从头再来时，我新建一个账户而不是重置旧账户，以便历史账务不被抹掉。

## 跨角色规则和外部约束

本章是换任何方案都必须成立的规则：先列交易所和税务的现行规定，再列发起者确认的系统级约束，最后列第一版明确不做的内容。

### 1. 交易所与税务规定

以下口径于 2026-09-24 按《上海证券交易所交易规则（2026 年修订）》《深圳证券交易所交易规则（2026 年修订）》及税务、中国结算公告核实，规则变更时更新本节。

- 1.1 交易日与时段：只在沪深交易所交易日交易，周末和法定节假日休市。开盘集合竞价 9:15 至 9:25，连续竞价 9:30 至 11:30 和 13:00 至 14:57，收盘集合竞价 14:57 至 15:00。全部 A 股可在 15:05 至 15:30 以当日收盘价进行盘后固定价格交易，当日 15:00 仍处于停牌状态的股票不进行。
- 1.2 T+1：当日买入的股份当日不可卖出，次一交易日起可卖。
- 1.3 申报数量：买入为 100 股整数倍，卖出时不足 100 股的零股须一次性卖出；科创板股票买入不少于 200 股，超过 200 股的部分以 1 股递增，卖出时不足 200 股的余股须一次性卖出。单笔申报上限：沪深竞价交易 100 万股；创业板限价申报 30 万股、市价申报 15 万股；科创板限价申报 10 万股、市价申报 5 万股；盘后固定价格交易 100 万股。
- 1.4 价格精度：股票申报价格最小变动 0.01 元。
- 1.5 涨跌幅限制：主板股票为前收盘价的 ±10%，含 ST 和 *ST 股票（2026 年 7 月 6 日起由 ±5% 调整为 ±10%）；创业板、科创板股票为 ±20%；新股上市前 5 个交易日不设涨跌幅。买入申报价不得高于涨停价，卖出申报价不得低于跌停价。
- 1.6 停牌：停牌期间不能成交。
- 1.7 风险警示股（ST、*ST）：只能以限价委托买卖；单个投资者当日累计买入同一只风险警示股不得超过 50 万股。
- 1.8 印花税：股票卖出按成交金额 0.05% 单边缴纳，买入不缴（2023 年 8 月 28 日起）。
- 1.9 过户费：股票按成交金额 0.001% 双向收取（2022 年 4 月 29 日起）。
- 1.10 佣金：由券商自定。发起者实际券商的费率为成交金额的 0.013%（万分之 1.3），最低 5 元；本系统按账户参数配置，默认取该值。
- 1.11 除权除息：送转股后持仓数量增加、每股成本相应摊薄；现金分红在到账日计入现金。

### 2. 系统级约束

- 2.1 成交价格必须来自真实市场行情；行情缺失或异常时不成交、不臆造价格，并留下记录。
- 2.2 现金账户：买入金额加费用不得超过可用现金；卖出不得超过可卖数量；不允许透支、卖空和任何形式的杠杆。
- 2.3 账务可靠：服务重启后所有账户数据不丢失；成交记录只增不改不删；持仓、现金和净值可由成交记录重新推导并核对；账务修正只能通过新增冲正记录完成。
- 2.4 单人使用：不需要账号体系；服务在本机或内网运行，不面向公网。
- 2.5 行情环境：行情来自外部公开数据源，可能延迟、限流或缺失；系统必须在这种条件下保持账务正确，宁可不成交也不错误成交。
- 2.6 时间口径：所有时间按北京时间。
- 2.7 完整留痕：账户上发生的所有操作都必须按时间记录并可按账户回看，包括每一次下单（含被拒绝、撤销和失效的）、成交、结算、除权除息，以及账户状态和参数的变更；记录要带当时的依据（如成交或拒绝所依据的行情），以便事后复盘每一笔决策和结果。

### 3. 第一版范围边界

- 3.1 不做历史行情回放模式，账户只向前运行；复盘靠 2.7 完整留痕的记录。
- 3.2 不模拟部分成交和盘口深度；一笔订单要么全额成交，要么等待或失败。
- 3.3 不做 tick 级撮合，盘中以分钟级或更细的行情快照为准。
- 3.4 不计现金分红的红利税，分红按税前金额入账。
- 3.5 不含北交所股票，也不含 ETF 等基金。
- 3.6 资金只在开户时一次注入，不支持追加和提取。
- 3.7 不处理配股、增发等需要主动申购的公司行动。
- 3.8 程序接入只提供 HTTP API；MCP 工具封装，以及 stockAI、signal-forge 等既有项目的迁移与对接，列为后续范围。
